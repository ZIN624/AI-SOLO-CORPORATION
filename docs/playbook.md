# 運用プレイブック

AI社員10人を実際に「回す」ための型。

---

## 1. 一日の型

### 朝（5分）— 秘書に状況を出させる
```
secretary に案件台帳を確認させて、今日やるべきことを3つに絞って
```

### 日中 — 実務は並列で投げる
一度に複数の社員を同時に動かせる。依存関係が無い作業は並列で指示する。
```
researcher に競合A社の料金改定を調べさせて、
同時に writer に来週のブログ記事の構成案を作らせて
```

### 夕方（5分）— 記録を残す
```
secretary に今日の日報を作らせて、案件台帳を更新して
```

---

## 2. 週の型

| 曜日 | やること | 指示例 |
|---|---|---|
| 月 | 今週の優先順位決め | `ceo と marketer に今週の打ち手を検討させて` |
| 水 | 数字の確認 | `analyst に今月のKPIを集計させて` |
| 金 | 週報と振り返り | `secretary に週報を作らせて、ceo に来週の重点を出させて` |

---

## 3. 定期実行（投稿でいう「Zapier」の部分）

Claude Code には定期実行の仕組みがあり、決まった時刻に自動で社員を働かせられる。

### ブラウザ版・Web版の場合 — Routines
「毎朝8時に〇〇して」と頼めば、定期実行として登録される。

例:
```
毎朝8時に researcher で「自社の業界の前日のニュース」を調べさせて、
work/ に日付付きで保存する定期実行を作って
```

### ローカル CLI の場合 — cron / hooks
`.claude/settings.json` の hooks や OS の cron から `claude -p "..."` を呼ぶ。

```bash
# 例: 毎朝8時に業界ニュースをまとめる
0 8 * * * cd ~/AI-SOLO-CORPORATION && claude -p "researcher に業界の最新ニュースを調べさせ、work/ に保存して" >> logs/cron.log 2>&1
```

### 定期実行に向いている仕事 / 向いていない仕事

| 向いている | 向いていない |
|---|---|
| 情報収集・ニュース要約 | 顧客への返信の送信 |
| KPIの集計・レポート生成 | 金額が絡む判断 |
| 案件台帳の棚卸し・締切チェック | SNSへの自動投稿（内容が確認されない） |
| 記事の下書き作成 | 契約・見積の確定 |

**原則: 「作る」は自動化してよい。「出す」は人間が押す。**

---

## 4. 増やし方（重要）

最初から10人フル稼働させない。次の順で増やす。

1. **researcher / writer / programmer** の3人から始める（効果が出るのが速い）
2. 実際に使った業務で「毎回同じ手順を説明している」と気づいたら、それを `.claude/skills/` にマニュアル化する
3. 手順が安定したものだけ定期実行に乗せる
4. 業務量が増えてから secretary / analyst を足す
5. 顧客が付いてから sales / office を足す

---

## 5. スキル（業務マニュアル）の作り方

同じ指示を3回した業務は、マニュアル化のサイン。

`.claude/skills/<業務名>/SKILL.md` を作る:

```markdown
---
name: 月次請求
description: 毎月の請求書を作成する手順。「請求書を作って」「月次請求」で使う。
---

## 手順
1. data/案件台帳.md から今月完了した案件を抽出する
2. 各案件の金額を data/料金表.md で確認する
3. xlsx スキルで請求書テンプレートに転記する
4. 【要確認】の項目を一覧にして社長に提示する
5. 承認後、work/YYYY-MM/請求書_<顧客名>.xlsx として保存する
```

これで「請求書を作って」の一言で毎回同じ品質の仕事が出る。**ここが一人会社の本体**です。

---

## 6. 動作環境の使い分け

| | 使いどころ |
|---|---|
| **ローカル CLI（VS Code のターミナルで `claude`）** | 本命。ファイル操作、MCP接続、長時間作業、差分を見ながらの承認 |
| **Web / ブラウザ版** | 外出先からの指示出し、投げっぱなしのタスク、定期実行の管理 |

同じリポジトリを両方から触れるので、**ローカルで作り込み、外からはリモコンとして使う**のが基本形。

## 7. うまくいかないときのチェックリスト

- [ ] `CLAUDE.md` の会社概要は埋まっているか（空欄だと全員が的外れになる）
- [ ] 指示が抽象的すぎないか（「いい感じに」ではなく、誰に何を何のために）
- [ ] 1人に詰め込みすぎていないか（役割を分けて並列にする）
- [ ] 成果物がファイルとして残っているか（チャットで消えていないか）
- [ ] 同じ説明を毎回していないか（スキル化のサイン）
